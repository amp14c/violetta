Data sources

Source What it has Format Used for
PATH Ridership Statistics, Port Authority of NY & NJ Monthly reports (2012–present) and hourly reports (2017–present, plus Jul 2014 and Nov 2016 snapshots), by station PDF only: no API, no CSV Main source for all charts
FTA National Transit Database: Complete Monthly Ridership (PATH = NTD ID 20098) · NTD monthly ridership page Monthly system-wide unlinked trips, 2002–present CSV / API Cross-check
NY Open Data: PATH Monthly Ridership, Beginning 1996 (data.gov listing) Monthly system total in thousands. Stopped updating in 2016 CSV / API Cross-check
NY Open Data: PATH Average Weekday & Weekend Ridership, Beginning 1996 (data.gov listing) Average weekday and weekend ridership, system total. Stopped in 2016 CSV / API Not used (covered by PDFs)
APTA Quarterly Ridership Reports (archive) Quarterly unlinked trips by agency (listed as “Port Authority of NY & NJ”, heavy rail) PDF Not used (quarterly, system only)

Why PDFs, when there are CSVs? The two free machine-readable sources don’t cover what this project needs. NY Open Data stopped in 2016. The National Transit Database is current but has system totals only, with no stations and no hours. The Port Authority’s PDFs are the only source with station-level and hourly detail up to the present. So the PDFs are the main source, and the CSV/API sources are used to check them.

The PDFs live at https://www.panynj.gov/content/dam/path/about/statistics/<file>.pdf. File names vary by year (2012_PATH_Ridership_Report, 2015-PATH-Ridership-Report, …-hourly-… vs …-Hourly-…), so scripts/01_download.py lists each one explicitly.

Pipeline: step by step

Step Script / file Input → output What it does
1. Download scripts/01_download.py PANYNJ, NY Open Data and NTD URLs → data/raw/ Downloads 15 monthly and 12 hourly PDF reports, plus the two CSV/API sources. Checks each PDF is valid and skips files already on disk.
2. Parse monthly scripts/02_parse_monthly.py data/raw/pdf/monthly_*.pdf → data/processed/path_monthly_by_station.csv, path_monthly_system.csv, crosscheck_system_totals.csv Reads the PDF text layer (pdfplumber), finds each month’s page, extracts both station tables and the day-count row, standardises station names, validates, and compares with NY Open Data and NTD.
3. Parse hourly scripts/03_parse_hourly.py data/raw/pdf/hourly_*.pdf → data/processed/path_hourly.csv, hourly_parse_issues.csv Reads every station page (section label, station, 24 hours × 8 columns) and reshapes it to a long “tidy” table. Any row it can’t parse is logged.
4. Charts pathviz.py processed CSVs → Plotly figures One module defines every chart, so the dashboard and the presentation always match.
5. Publish path/dashboard.qmd, path/slides.qmd, _quarto.yml → website (_site/) Quarto renders the dashboard, slides and this page. GitHub Pages hosts them.

python scripts/02_parse_monthly.py # step 2

Problems the parser handles

  • Two tables per page. Each station appears twice on a monthly page: first as totals and averages, then as average-daily and totals by day type. The parser tells them apart by order.
  • Renamed stations. “Pavonia/ Newport” → “Newport”, “WTC” → “World Trade Center”, “Christopher St.” → “Christopher Street”.
  • Section labels change format across years (“January 2021”, “Jun 2025”, “2026-Jan”, “YTD 2019”, “2025 Annual”), and ASCII and Unicode hyphens are mixed.
  • Blank holiday columns in months with no holiday (e.g. Mar, Apr and Aug 2026) leave 6 values per row instead of 8.
  • One-off snapshot reports (July 2014, November 2016) use slightly different headers.
  • macOS file names are case-insensitive, so Hourly.pdf and hourly.pdf would overwrite each other. Files are saved as hourly_2025.pdf etc.

Data definitions

What is counted. Every number comes from PATH’s faregates, the turnstiles and TAPP gates riders pass through. There are two kinds of count:

Term What it means Which station it describes Where it’s used
Entry (also “trip” or “ridership”) A person passing into the system through a faregate The origin: the station where the trip starts Monthly data (all charts on the Overview and Monthly pages), and the hourly charts unless marked “exits”
Exit A person passing out through a faregate The destination: the station where the trip ends Hourly data only, where marked

Example: someone who commutes from Hoboken to 33rd Street and back counts as an entry at Hoboken in the morning and an entry at 33rd Street in the evening. That’s two trips. Their morning exit is counted at 33rd Street.

How exits are counted. PATH riders tap in only. Nobody taps out, so exits don’t come from fare payments. The hourly reports are labelled “Turnstile Count” (through 2023) and “Legacy and TAPP Faregates Count” (from 2024). Exits are the number of people physically passing out through the exit turnstiles or faregates, and the gate counts each passage without charging. Because entries and exits aren’t linked to a card, the data can’t say where a particular rider went. There are no origin–destination pairs, only how many trips started and ended at each station.

Entries vs. exits don’t match system-wide after 2021. Through 2019, system-wide weekday exits were within about 1% of entries, as expected. Since 2022 exits have run about 9–12% higher than entries. The reports don’t explain this. Possible reasons include entries that aren’t counted (cross-honor, freewheeled, fare evasion) and differences between the old and new gates. For this reason the dashboard uses entries for all ridership totals, and uses exits only to show when trips end.

Other terms

  • Average weekday / Saturday / Sunday / holiday. Total entries on that type of day, divided by the number of those days in the month. Holidays are days PATH runs a holiday schedule, and they’re left out of the weekday, Saturday and Sunday averages.
  • Rush hours. In this project: 7–9 am and 5–7 pm (four one-hour periods).
  • Cross-honor. Tickets from other operators (e.g. NJ Transit) that PATH accepts during service disruptions. These are not included in the counts.
  • Freewheeled entries. Excluded from 2024 on, per the report headers. The reports don’t define the term. It usually means gates set to free entry, with no fare charged.
  • Legacy + TAPP. From 2023, counts combine the old turnstiles and PATH’s new contactless TAPP faregates.
  • Linked vs. unlinked trips. The PATH reports count linked trips: one faregate entry per journey, even if the rider changes trains. The federal National Transit Database counts unlinked trips, meaning every boarding, so a transfer counts twice. That’s why NTD totals run about 6–11% higher than the PATH reports every month.

Data dictionary

data/processed/path_monthly_by_station.csv: one row per station per month.

Column Type Description
date date First day of the month
year, month int Calendar year and month (1–12)
station text Station name (13 stations)
state text NJ or NY
total int Entries in the month
avg_weekday, avg_saturday, avg_sunday, avg_holiday int Average entries per day of that type
avg_daily int Total ÷ days in the month
weekday_total, saturday_total, sunday_total, holiday_total int Total entries on all days of that type
n_weekdays, n_saturdays, n_sundays, n_holidays int Number of days of each type in the month

data/processed/path_monthly_system.csv: same columns, one row per month for the whole system (no station / state).

data/processed/path_hourly.csv: long format, one row per period × station × hour × day type × direction.

Column Type Description
year int Report year
period text month (one month) or annual (whole-year or year-to-date average)
month int 1–12 when period is month, blank otherwise
station text Station name, or System-wide
hour int Hour of day, 0–23 (0 = midnight to 1 am)
day_type text weekday, saturday, sunday, holiday
direction text entry (trip starts here) or exit (trip ends here)
avg_count int Average number of people through the faregates in that hour

data/processed/crosscheck_system_totals.csv: monthly PDF totals next to NY Open Data (nyod_thousands) and NTD (upt, unlinked passenger trips), with % differences.

Limitations

  • Faregate entries are not unique people. A daily commuter makes about 40 trips a month. Fare evasion, cross-honored and freewheeled entries are not counted.
  • Closures show up as near-zero values, not as missing data. Examples: WTC and Exchange Place weekends in much of 2014, Hoboken in February 2025 (about 2,700 a weekday and zero on weekends), and low WTC weekend values in 2019. They’re real counts, but they pull averages down.
  • Hourly data starts in 2017, plus one-month snapshots for July 2014 and November 2016. Exits are only available in the hourly data.
  • The current year is partial (through the latest published month).
  • Fare-system change. The move from old turnstiles to TAPP faregates (2023–25) changed the counting equipment. Small shifts in that period may partly reflect measurement.
  • Rounding. The PDFs round averages to whole people, so sums of hourly values can be off by a few.
